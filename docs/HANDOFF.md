```text
  repository.bundle              дополнительная автономная копия Git
  releases/                      подписанный APK 0.2.1 и публичный отчёт проверки
  previews/                      Android-скриншоты и веб-превью
  web-preview/                   готовая статическая веб-сборка
  tools/
    node/                        Node.js 24.22.2 + npm, Windows x64
    java/                        Java Runtime 21.0.13, Windows x64
    android-build-tools/         Android build-tools 36.0.0, Windows x64
    7zip/                        распаковка зашифрованного приватного архива
  Use-Tools.ps1                  подключение portable Node к текущей консоли
  Sign-Next-Apk.ps1              подпись очередного unsigned release APK
  serve-preview.mjs             локальный просмотр готовой веб-сборки
```

Отдельный файл **`Chalanger-Signing-PRIVATE-2026-11-08.7z`** содержит зашифрованную копию ключа, настроек с паролем и сертификата. Пароль этого архива находится в отдельном защищённом файле на исходном компьютере: `Downloads/Chalanger Signing/Пароль архива переноса.txt`. Перенести пароль отдельно, например через свой менеджер паролей. В этой инструкции паролей нет.

В комплект не входят авторизация GitHub, учётная запись RuStore, личные данные телефона, `node_modules`, кэши сборки, Android Studio и полный JDK/Android SDK. Зависимости восстанавливаются через `npm ci`. Portable-инструменты рассчитаны на **Windows x64**.

## Первый запуск на другом компьютере

1. Перенести основной ZIP, приватный 7z и пароль приватного архива. Распаковать основной ZIP.
2. Открыть PowerShell в распакованной папке `Chalanger`.
3. Подключить Node в текущую консоль:

```powershell
. .\Use-Tools.ps1
node --version
npm.cmd --version
```

Если Windows блокирует запуск скачанных скриптов, можно разрешить его только для текущего окна PowerShell: `Set-ExecutionPolicy -Scope Process Bypass`. Не менять системную политику постоянно.

4. Распаковать приватный архив в **`private-signing`** рядом с `project`. Команда спросит пароль; не вставлять его в текст команды или в Git:

```powershell
& .\tools\7zip\7z.exe x '..\Chalanger-Signing-PRIVATE-2026-11-08.7z' '-oprivate-signing'
```

Если архив лежит в другом месте, указать его фактический путь. В `private-signing` должны оказаться непосредственно `chalanger-release.p12` и `signing-settings.json`, без лишнего вложенного каталога.

5. Перенастроить путь к существующему ключу для нового компьютера:

```powershell
& .\project\scripts\restore-signing-location.ps1 -PrivateDirectory .\private-signing
```

Скрипт меняет только путь к PKCS12 в настройках и защищает каталог средствами Windows. Ключ, alias, пароль и сертификат остаются прежними. Исходные настройки содержат путь старого компьютера — этот шаг обязателен перед подписью.

6. Проверить проект:

```powershell
cd .\project
git status
git branch --show-current
git remote -v
npm.cmd ci
npm.cmd test
npm.cmd run dev
```

Рабочая ветка должна быть `codex/android-first-release`, origin — GitHub URL выше. Для push потребуется заново войти в свой GitHub на новом компьютере; чужие токены в комплект не переносились.

## Посмотреть готовую веб-версию без установки зависимостей

Из папки `Chalanger`:

## Как собирать следующие версии

### Вариант 1: GitHub Actions — без установки Android Studio

1. Внести изменения в `project`.
2. Увеличить `versionCode` в `android/app/build.gradle` **выше 3**; обновить `versionName`, `package.json`/lock и отображаемую версию. Для ближайшего следующего выпуска минимум `versionCode = 4`.
3. Выполнить подходящие проверки, commit и push в рабочую ветку.
4. Дождаться успешного workflow **Android and web checks**. Он собирает release, проверяет веб-интерфейс и Android-приложение в эмуляторе.
5. Скачать артефакт **`chalanger-release-unsigned`**, распаковать его. Нужен файл `outputs/apk/release/app-release-unsigned.apk`.
6. Из корня переносного комплекта подписать APK:

```powershell
& .\Sign-Next-Apk.ps1 `
  -UnsignedApk 'C:\путь\к\app-release-unsigned.apk' `
  -OutputApk 'C:\путь\к\Chalanger-next.apk' `
  -PrivateDirectory .\private-signing
```

`Sign-Next-Apk.ps1` использует инструменты и ключ по относительным путям. При необходимости сначала запускает восстановление пути к ключу. Существующий выходной APK не перезаписывает: выбирать новое имя для новой версии.

Основной `project/scripts/sign-release.ps1` проверяет package ID, запрещает подпись debuggable APK постоянным ключом, сверяет сертификат с закреплённым отпечатком и создаёт публичный отчёт `.apk.verification.json`. Пароль не выводится. На Windows учтено ограничение `aapt` на абсолютные пути с кириллицей.

### Вариант 2: локальная Android-сборка

Нужны **JDK 21**, Android Studio/SDK 36 и Node 24. В комплекте есть **JRE для подписи**, а не JDK для компиляции. После установки JDK/SDK:

```powershell
cd .\project
npm.cmd ci
npm.cmd run android:sync
cd android
.\gradlew.bat assembleRelease lintDebug
```

Без секретных переменных окружения получится unsigned release; подписать его тем же `Sign-Next-Apk.ps1`. Debug-сборки не передавать пользователю. Не коммитить `local.properties`, пароли, ключи или токены.

### Веб-проверки

```powershell
npm.cmd test
npm.cmd run build
npx.cmd playwright install chromium
npm.cmd run test:e2e
```

GitHub Pages собирает и публикует `dist` при push в `main`. Пока рабочая ветка не слита, новая версия сайта и документы на Pages не считаются опубликованными.

## Постоянная подпись и обновления

Сертификат SHA-256:

```text
d965f605f89206f88a847cc049e7ca6d5b8a29cefa6f5b810ca39291465555d8
```

Он закреплён в `project/android/release-certificate.sha256`. Публичный сертификат можно показывать; PKCS12 и `signing-settings.json` — закрытые материалы. Зашифрованный архив и пароль к нему хранить раздельно. Не запускать `new-signing-key.ps1`: ключ уже создан.

Для обновлений нужны одновременно тот же package ID, тот же ключ и растущий `versionCode`. Нельзя менять origin Capacitor `https://localhost` без миграции IndexedDB.

Старые APK 0.1/0.2 с суффиксом `-test.apk` имели временные подписи CI. Они больше не используются. Переход на постоянную подпись однократный:

1. В старом приложении «Палитра → Сохранить копию».
2. Проверить, что JSON сохранён вне приложения.
3. Удалить старую установку, установить `releases/Chalanger-0.2.1.apk`.
4. «Палитра → Восстановить из файла».

Следующие правильно подписанные версии устанавливаются через «Обновить», без удаления приложения. Факт успешного перехода на телефоне пользователь ещё не подтвердил. Время напоминания в JSON не входит.

## Что реализовано

- Личный альбом идей для рисования, «Идеи» и «Готово», создание/редактирование/удаление с отменой, жесты перемещения и удаления.
- Поиск, избранное, даты создания и завершения. Даты старых карточек не выдумываются.
- Палитра цветов и узоров, анимации, поддержка уменьшенного движения.
- Локальный генератор: 16 тем, «Сюжет», «Редизайн», «Челлендж», смешивание двух тем, своя тема, закрепление и повторная генерация частей задания. Это не сетевой ИИ.
- Темы Sims/Winx заменены оригинальными «Маленькая жизнь» и «Школа фей» по согласованию с пользователем.
- IndexedDB, офлайн PWA, обновление кэша. Android включает файлы интерфейса в APK и не запускает service worker.
- JSON-копии v2 и чтение старых v1. Лимит текста 1000 символов, файла 10 МБ, копии 10000 карточек; валидация до замены и подтверждение восстановления.
- Android: системное сохранение/открытие JSON без доступа ко всем файлам, «Поделиться», кнопка «Назад».
- Генератор уменьшен и учитывает системные безопасные отступы.
- Короткие карточки показывают звезду/меню в строке, длинные — компактной строкой снизу. Перестановка отключена при активном поиске/фильтре.
- Напоминание с анимированным переключателем. Native AlarmManager/receiver выбирает одну из 10 фраз при доставке, без повтора предыдущей; не требует запущенного JS, интернета или точных будильников. Есть восстановление после перезагрузки/смены времени/обновления.
- Иллюстрированное знакомство с милым персонажем, чередующимися картинками и короткими фразами. Документы и лицензии — внизу.
- Анимации «Идеи» при создании и возврате карточки; анимация папки при завершении.
- Release-подпись локально постоянным закрытым ключом. CI не получает ключ и больше не выдаёт debug APK пользователю.

## Проверки и ограничения

Прошли 5 тестов данных/генератора, 7 браузерных сценариев, Android build/lint и 2 instrumentation-теста на Android 15. Нативные тесты проверяют офлайн-запуск, сохранение после перезапуска Activity, безопасный отступ генератора, переключатель напоминания и разные фразы уведомлений. Это не заменяет проверку конкретного телефона и Android 8/WebView.

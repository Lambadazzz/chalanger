# Android: разработка и выпуск

## Требования

Node.js 24, JDK 21, Android SDK 36. В Android Studio открыть каталог android.

```sh
npm ci
npm test
npm run android:sync
cd android
./gradlew assembleDebug assembleRelease lintDebug
```

Windows: `gradlew.bat` вместо `./gradlew`.
CI делает те же проверки в `.github/workflows/android.yml`. Debug-сборка используется только в эмуляторе. Для доставки сохраняется неподписанный release APK в артефакт `chalanger-release-unsigned`; перед установкой он подписывается локально постоянным закрытым ключом.

Единый пакет: `ru.lambadazzz.chalanger`, версия `0.2.1`, versionCode `3`. При каждом обновлении увеличивать versionCode в android/app/build.gradle и подписывать тем же постоянным закрытым ключом.

Напоминания 0.2: DrawingReminderReceiver выбирает одну из 10 фраз непосредственно при доставке, без повторения предыдущей. AlarmManager планирует следующий местный день; время восстанавливается после перезагрузки, смены часов/часового пояса и обновления. Доступ к точным будильникам не требуется. Старое напоминание 0.1 переносится при открытии палитры. LocalNotifications оставлен для запроса разрешения и удаления старого расписания.

Старые тестовые APK 0.1/0.2 имели временные подписи разных запусков CI. Для перехода на 0.2.1 один раз экспортировать альбом в JSON, убедиться, что файл сохранён, удалить старую установку, установить подписанный release APK и импортировать JSON. Дальнейшие release APK с тем же пакетом и постоянным ключом обновляются поверх.

## Данные

IndexedDB сохраняется при обычном обновлении с тем же пакетом и подписью. Не менять origin Capacitor (`https://localhost`) без миграции. В браузере и Android это разные хранилища: перенос через JSON.

Формат копии v2 содержит даты и избранное. v1 принимается, неизвестные даты остаются null. Текущая версия не гарантирует открытие v2 в старой веб-версии. Альбом заменяется только после полной проверки и подтверждения. Максимум файла 10 МБ, текста 1000 символов, карточек в копии 10000.

Ручные JSON-копии не включают время напоминания; после переноса его настраивают отдельно. Автоматическое резервирование Android отключено. Не удалять/очищать приложение, если важный альбом ещё не экспортирован.

## Подпись release

Постоянный ключ и пароли не хранятся в репозитории. Для локальной сборки задать переменные окружения:

```text
ANDROID_KEYSTORE_PATH=/absolute/path/chalanger-release.jks
ANDROID_KEYSTORE_PASSWORD=...
ANDROID_KEY_ALIAS=...
ANDROID_KEY_PASSWORD=...
```

Затем `npm run android:sync` и `./gradlew assembleRelease`.
Без переменных release остаётся unsigned. Не использовать debug-ключ для магазина.

Проверить подпись утилитой Android SDK:

```sh
apksigner verify --verbose --print-certs app/build/outputs/apk/release/app-release.apk
```

Постоянный закрытый ключ создан для владельца и хранится в защищённой локальной папке `Downloads/Chalanger Signing`: зашифрованный PKCS12, настройки с паролем и публичный сертификат. Эта папка целиком нужна для будущих подписей; сохранить её закрытую резервную копию на другом носителе. В GitHub хранится только отпечаток публичного сертификата `android/release-certificate.sha256`.

Готовый unsigned APK подписывает `scripts/sign-release.ps1`: параметры `UnsignedApk`, `OutputApk`, `SigningSettings`, `JavaExecutable`, `ApkSignerJar`, `AaptExecutable`. Скрипт проверяет package ID, отказывается подписывать debuggable APK, сверяет сертификат с закреплённым отпечатком и записывает публичный отчёт `.verification.json`. Пароль передаётся подписи через временную переменную окружения и не выводится.

`scripts/new-signing-key.ps1` предназначен только для первоначального создания ключа и отказывается перезаписывать существующий. Повторно создавать ключ для обновлений нельзя. CI не получает секретов и не публикует приложение в магазин.

## Проверка интерфейса

```sh
npm run build
npx playwright install chromium
npm run test:e2e
```

Браузерные проверки покрывают пользовательские сценарии и PWA офлайн, но не заменяют Android-проверку системного выбора файлов, Share, кнопки Back и уведомлений.

## Офлайн и веб-версия

Vite собирает web в dist. build.mjs создаёт service worker со списком итоговых файлов и хешем содержимого. GitHub Pages публикует dist. В Android файлы включены в APK; service worker не запускается, обновления поступают через новый APK.
